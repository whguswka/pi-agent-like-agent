## 1. 반입과 배포 (배포 담당)
1. 인터넷 PC 에서 [GitHub 저장소](https://github.com/whguswka/pi-agent-like-agent) 의 **Code > Download ZIP** 으로 `pi-agent-like-agent-main.zip` 을 받습니다.
   - 판 번호는 저장소 첫 화면 파일 목록의 `VERSION` 에 있습니다 (예: `2026-10-06.1`). 바뀐 점과 바꾼 뒤 할 일은 [CHANGELOG.md](../CHANGELOG.md).
   - 예전 판이 필요하면(되돌리기 등) 저장소의 **Tags** 에서 그 판(`v<판 번호>`)의 zip 을 받습니다. 이름만 다를 뿐 같은 방법으로 깝니다.
2. 사내 반입 절차로 zip 을 업무망에 넘깁니다. 처음이거나 보안 검토가 필요하면 [반입 검토 자료](반입-검토-요청서.md)를 함께 냅니다.
   - 전송 시스템의 백신이 파일을 막으면 **파일을 고치거나 압축 방식을 바꾸지 말고** 보안 담당에게 검토를 요청합니다
     (pi 실행 코드는 압축(minify)된 JavaScript 라 오탐이 날 수 있습니다. 검토 자료 5장에 파일 해시 목록이 있습니다).
3. 받은 zip 을 동료가 가져갈 수 있는 곳(공유 폴더 등)에 둡니다. **이전 판 zip 도 지우지 말고** 함께 두면 되돌릴 때 씁니다 (5장).
4. 동료에게 알립니다: zip 위치, 바꾸는 명령(3장), 바뀐 점과 할 일([CHANGELOG.md](../CHANGELOG.md) 의 그 판). 처음 쓰는 사람에게는 [빠른 시작](빠른시작.md).

## 2. 처음 설치
준비물 ([README 1장](../README.md#1-준비물)): Git Bash, Python 3.8 이상, VS Code 1.93 이상(또는 Node 20.15 이상), Chrome(또는 Edge), Microsoft 365 Copilot 계정.

1. zip 을 업무 PC 로 가져옵니다 (예: `~/Downloads`). 이름이 `pi-agent-like-agent-main (1).zip` 처럼 바뀌었으면 아래 명령의 이름도 바꿉니다.
   이미 `~/tools/pi` 가 있으면 설치하지 말고 3장으로 갑니다.
2. Git Bash 에서:
   ```bash
   cd ~/Downloads
   mkdir -p ~/tools && unzip -q pi-agent-like-agent-main.zip -d ~/tools/ && mv ~/tools/pi-agent-like-agent-main ~/tools/pi
   bash ~/tools/pi/check-node.sh
   bash ~/tools/pi/install.sh pc
   ```
   - `check-node.sh` 의 마지막 줄이 `결과: 사용 가능` 또는 `결과: 호환 모드로 사용 가능` 이면 됩니다.
     `결과: 사용 가능한 Node 없음` 이면 [README 2-2](../README.md#2-2-nodejs-확인) 대로 준비한 뒤 `bash ~/tools/pi/install.sh pc` 를 다시 실행합니다.
3. Git Bash 창을 **새로** 열고 `pi --version` 을 쳐 봅니다 (판 번호가 나오면 설치된 것).
4. 작업 폴더에서 `pi` 를 실행합니다. Chrome 전용 창이 뜨면 그 창에서 **Copilot 에 로그인**합니다 (처음 한 번만).
   시작 화면의 `Warning: fd not found ...`, `Warning: ripgrep not found ...` 두 줄은 늘 나오는 것이니 무시합니다.
   Copilot 채팅 화면이 나온 뒤에 pi 에 첫 요청을 보냅니다 (첫 요청은 새 대화를 여느라 1~2분 걸립니다).
5. 시험: `hello.py 를 만들어서 hello 를 출력하고 실행해줘` → 파일이 생기고 결과가 나오면 끝입니다.
6. 안 되면 8장.

## 3. 새 판으로 바꾸기
지금 판을 확인합니다:
```bash
cat ~/tools/pi/VERSION 2>/dev/null || echo "판 번호 없음 (예전 판)"
```

### 3-1. 바꾸기 (모든 판 공통)
1. 실행 중인 pi 를 모두 끕니다 (`/quit`). Copilot 전용 창과 `~/tools/pi` 를 연 탐색기·터미널도 닫습니다.
2. Git Bash 에서, 받은 zip 의 위치·이름을 `Z=` 뒤에 적고 실행합니다:
   ```bash
   cd ~
   Z=~/Downloads/pi-agent-like-agent-main.zip
   unzip -o -j -q "$Z" '*/update.sh' -d ~/tools && bash ~/tools/update.sh "$Z"
   ```
   - 새 판의 `update.sh` 만 꺼내 `~/tools/update.sh` 에 두고 실행합니다. 옆의 `~/tools/pi` 를 새 판으로 바꾸고, 끝나면 꺼낸 파일은 지웁니다.
     지금 판에 `update.sh` 가 없어도(2026-10-02 이전 판) 이 방법으로 바꿉니다.
   - 이미 새 판(update.sh 가 있는 판)을 쓰고 있으면 `bash ~/tools/pi/update.sh "$Z"` 로 해도 같습니다.
3. 마지막에 `[update] 완료: <지금 판> -> <새 판>` 이 나오면 4장으로 갑니다.
   바로 위의 `[update] 이 판에서 바뀐 점` 에 '할 일' 이 있으면 그것도 합니다 (2026-10-06.1 부터. 전체는 `~/tools/pi/CHANGELOG.md`).

| 메시지 | 할 일 |
|---|---|
| `zip 파일이 없습니다` | `Z=` 뒤의 이름과 위치를 확인 (`ls ~/Downloads/*.zip` 으로 받은 파일 이름을 볼 수 있음. 이름에 공백이 있으면 `Z="$HOME/Downloads/pi-agent-like-agent-main (1).zip"` 처럼 따옴표) |
| `이미 같은 판(...)입니다` | 받은 zip 이 새 판인지 확인 (브라우저가 `(1)` 을 붙여 저장한 새 파일일 수 있음). 같은 판을 다시 깔려면 끝에 `--force` |
| `지금 폴더의 이름을 바꾸지 못했습니다 (사용 중)` | pi, Copilot 전용 창, `~/tools/pi` 를 연 탐색기·터미널·VS Code 를 닫고 다시. 아무것도 바뀌지 않은 상태입니다 |
| `지난번 이전 판 폴더(...pi.old)를 지우지 못했습니다` | `~/tools/pi.old` 를 연 창을 닫고 다시 |
| `확인: 이전 판의 copilot/bridge.json 에서 새 판과 값이 다른 항목: ...` | 예전 판에서 직접 고친 설정입니다. 그 항목을 내 설정 파일로 옮깁니다 (6장) |
| `install.sh 가 실패했습니다` | 화면을 찍어 보내 주세요. 이전 판은 `~/tools/pi.old` 에 있습니다 (5장) |
| `치움: .../extensions/... (이 판에는 없는 확장 -> extensions.removed/)` | 정상. 새 판에서 빠진 확장을 옮겨 둔 것 |

- 아주 예전 판(Edge 전용 창을 쓰던 판)에서 바꾸면 새 판은 Chrome 전용 창을 띄웁니다. 그 창에서 Copilot(과 Kubeflow)에 다시 로그인하거나,
  계속 Edge 를 쓰려면 내 설정 파일에 `"browser": "edge"` 를 넣습니다 (6장).

### 3-2. update.sh 가 안 될 때 (손으로)
3-1 이 어떤 이유로든 안 되면 같은 일을 손으로 합니다. **한 줄로** 실행해야 중간에 실패할 때 거기서 멈춥니다.
```bash
cd ~
Z=~/Downloads/pi-agent-like-agent-main.zip
rm -rf ~/tools/pi.old ~/tools/pi-agent-like-agent-main && mv ~/tools/pi ~/tools/pi.old && unzip -q "$Z" -d ~/tools/ && mv ~/tools/pi-agent-like-agent-main ~/tools/pi && bash ~/tools/pi/install.sh pc && cat ~/tools/pi/VERSION
```
- 마지막에 새 판 번호가 나오면 된 것입니다.
- 도중에 멈췄는데 `~/tools/pi` 가 없고 `~/tools/pi.old` 만 있으면 `mv ~/tools/pi.old ~/tools/pi` 로 원래대로 돌립니다.
- 예전 판에서 `copilot/bridge.json` 을 직접 고쳤는지는 이렇게 확인합니다 (고친 항목이 나오면 6장대로 옮김):
  ```bash
  PYTHONIOENCODING=utf-8 python - <<'EOF'
  import json, os
  t = os.path.expanduser("~/tools")
  load = lambda p: {k: v for k, v in json.load(open(p, encoding="utf-8-sig")).items() if not k.startswith("_")}
  old, new = load(t + "/pi.old/copilot/bridge.json"), load(t + "/pi/copilot/bridge.json")
  print({k: old[k] for k in old if old[k] != new.get(k)} or "고친 항목 없음")
  EOF
  ```

## 4. 바꾼 뒤 점검
새 판으로 바꿀 때마다 4-1 을 합니다. 4-2 는 2026-10-04.1 이상으로 처음 바꾼 뒤 한 번 합니다 (그 뒤로는 바뀐 점에 '요약' 이 있을 때만). 4-3 은 원할 때만 합니다.

### 4-1. 5분 점검
1. Git Bash 창을 새로 열고 작업 폴더에서 `pi` 를 실행합니다. 처음에 `[pi] 중계 서버를 새 코드로 다시 켭니다` 가 나오면 정상입니다.
   시작 화면의 `Warning: fd not found ...`, `Warning: ripgrep not found ...` 두 줄도 늘 나오는 것이라 무시합니다 (쓰지 않는 검색 도구 안내).
2. `/doctor` 를 칩니다. '버전' 줄이 `판 <새 판> / pi 0.87.1 / 중계기 코드 <...>` 이고, '중계 서버' 줄에 `코드와 다름` 이 없어야 합니다.
3. 새 기능을 한 번씩 써 봅니다.

| 해 볼 것 | 보여야 할 것 |
|---|---|
| `/kit` | 입력창 위 도움말에 `작업 /plan ...`, `@ 파일 고르기` 줄 |
| `/plan` 뒤에 `hello.txt 에 오늘 날짜를 적어 줘` | 상태 줄 `계획 모드 · 읽기만` → Copilot 의 번호 붙은 계획 → `이 계획대로 진행할까요?` 선택 창 |
| 선택 창에서 `진행 (확인: 바꿀 때마다 확인)` | 파일을 만들기 전에 `새 파일: hello.txt` 확인 창, 입력창 위에 `계획 진행` 목록 |
| `/mode auto` | 상태 줄의 모드 표시가 사라짐 |
| 입력창에 `@` | 작업 폴더의 파일 목록 (`@hel` 처럼 더 치면 좁혀짐, `Tab` 으로 고름) |
| `/undo` | `되돌릴까요?` → 방금 만든 `hello.txt` 가 지워짐 |
| `/remember 답은 짧게` | `어디에 기억할까요?` → 고르면 `기억했습니다` |
| `/quit` 으로 끈 뒤 전용 창의 Copilot 왼쪽 목록 | 방금 pi 가 쓴 대화가 잠시 뒤 지워짐 (남아 있으면 그 화면과 다음 `/doctor` 화면을 보내 주세요) |

4. 이상하면 그 화면을 찍어 보내 주세요 (8장). 진행 선택 창이 뜨지 않으면 Copilot 이 번호 붙은 계획을 쓰지 않은 것입니다. 그 답 화면을 함께 보내 주세요.

### 4-2. 요약 점검
10~15분 걸립니다. 대화가 아주 길어지면 pi 가 앞 대화를 Copilot 에게 요약시키고, 그 요약을 넣은 새 대화로 이어 갑니다
(`/compact` 와 같은 일. 맥락 한도에 가까워져 pi 가 스스로 하는 자동 요약도 같은 요청입니다).
실제 Copilot 이 요약을 제대로 써 주는지는 회사에서만 볼 수 있어서, 지워도 되는 시험 폴더에서 한 번 해 봅니다.
평소 설정은 최근 대화(약 8만 자)를 그대로 두고 그 앞만 요약하므로 짧은 시험 대화에는 요약할 것이 없습니다.
그래서 시험 폴더에만 최근 대화를 거의 남기지 않는 설정을 둡니다.

1. 실행 중인 pi 를 모두 끄고, Git Bash 에서:
   ```bash
   mkdir -p ~/pi-compact-test/.pi && cd ~/pi-compact-test
   echo '{"compaction": {"keepRecentTokens": 1}}' > .pi/settings.json
   pi --approve
   ```
   - `--approve` 는 이 폴더의 `.pi/settings.json` 을 이번 실행에만 쓰겠다는 뜻입니다.
     빠뜨려서 `Trust project folder?` 가 나오면 `Trust (this session only)` 를 고릅니다.
2. 아래 둘을 차례로 보냅니다 (앞의 것이 끝난 뒤 다음): `hello.py 를 만들어서 hello 를 출력하고 실행해줘`, `hello.py 가 오늘 날짜도 출력하게 고쳐줘`
3. 확인합니다.

| 해 볼 것 | 보여야 할 것 |
|---|---|
| `/compact` | 몇 분 동안 `Compacting context... (escape to cancel)` → `[compaction]` 아래 `Compacted from <숫자> tokens (ctrl+o to expand)` |
| `Ctrl+O` | 펼친 요약: `## Goal`, `## Progress`, `## Next Steps` 같은 제목(한국어일 수도 있음) 아래에 hello.py 를 만들고 날짜 출력을 넣은 일. 끝의 `<modified-files>` 목록은 pi 가 붙인 것 |
| `지금까지 한 일을 한 줄로 알려줘` | hello.py 를 만들고 고친 일을 말함 (요약을 넣은 새 대화에서 답한 것) |

   - `/compact` 동안 상태 줄에 `Copilot: 새 대화 여는 중 12초`, `Copilot: 답 기다리는 중 5초` 처럼 진행이 나옵니다. 끝나면 사라집니다.
     요약 요청(한두 번)과 그다음 질문이 각각 새 대화라 Copilot 새 대화가 두세 번 열립니다. 앞 대화는 자동으로 지워집니다.
     **Esc 를 누르면 요약이 멈추니** 끝날 때까지 기다립니다.
4. `/quit` 으로 끄고 시험 폴더를 지웁니다: `cd ~ && rm -rf ~/pi-compact-test`

| 메시지 | 뜻과 할 일 |
|---|---|
| `Error: Compaction failed: Nothing to compact (session too small)` | 시험 설정이 읽히지 않은 것. `~/pi-compact-test` 에서 `pi --approve` 로 실행했는지, `cat ~/pi-compact-test/.pi/settings.json` 이 위와 같은지 확인 |
| `Error: Compaction cancelled` | Esc 로 멈춘 것. `/compact` 를 다시 (Copilot 이 멈춘 요약에 답하기를 마칠 때까지 잠시 기다렸다 시작함) |
| 그 밖의 `Error: Compaction failed: ...` | 그 화면과 `/doctor` 화면을 보내 주세요 (8장) |
| 요약은 됐는데 마지막 답이 엉뚱함 | 그 답 화면과 `Ctrl+O` 로 펼친 요약 화면을 보내 주세요 |

### 4-3. (선택) 질문 수 한도 점검
Copilot 대화 하나에 질문이 `max_questions_per_chat`(기본 100)개 쌓이면, 중계 서버가 새 대화를 열고 지침과 최근 기록을 다시 넣어 하던 일을 이어 갑니다.
평소 한두 시간 쓰면 저절로 일어나므로 미리 보고 싶을 때만 합니다. 10분쯤 걸립니다.

1. 내 설정 파일 `~/.pi/agent/bridge.json` 에 `"max_questions_per_chat": 6` 을 넣고 (적는 법은 6장) 6장의 '고친 뒤 적용' 대로 다시 켭니다.
   pi 는 빈 폴더에서 실행합니다: `mkdir -p ~/pi-limit-test && cd ~/pi-limit-test && pi`
2. 4-2 의 2번 작업 둘을 보내고, 이어서 `처음에 만든 파일 이름이 뭐였지?`
   - pi 가 파일을 만들고 실행하는 동안 Copilot 에 여러 번 묻기 때문에, 작업 중간에 상태 줄에 `Copilot: 새 대화 여는 중` 이 다시 나옵니다.
   - 작업이 끊기지 않고 끝나고, 마지막 질문에 hello.py 라고 답하면 됩니다.
   - `/quit` 으로 끈 뒤 `grep "질문 수 한도" ~/.pi/agent/copilot-relay.log | tail -3` 을 치면 `설정한 대화당 질문 수 한도(6개)에 닿았습니다` 줄이 보입니다.
3. **꼭 되돌립니다:** 내 설정 파일에서 `"max_questions_per_chat": 6` 을 지우고 다시 '고친 뒤 적용'. 그대로 두면 몇 번 물을 때마다 새 대화를 여느라 아주 느려집니다.
   시험 폴더도 지웁니다: `cd ~ && rm -rf ~/pi-limit-test`

## 5. 이전 판으로 되돌리기
새 판에 문제가 있으면 이전 판으로 돌아갑니다. `~/tools/pi.old` 에는 **바로 앞 판 하나만** 남습니다 (다음 업데이트 때 지워짐). 이전 판 zip 을 보관해 두면 언제든 되돌릴 수 있습니다 (없으면 GitHub 의 Tags 에서 그 판의 zip 을 받아 반입).

### 5-1. 이전 판 zip 이 있으면
```bash
cd ~

```

- 2026-10-02 이전 판(update.sh 가 없는 판)으로 되돌렸다면, 다시 새 판으로 갈 때도 3-1 의 방법을 씁니다.

### 5-2. zip 이 없으면 (`~/tools/pi.old` 로)

2. Git Bash 에서 (넷째 줄은 되돌린 판에 없는 키트 확장만 `extensions.removed` 로 옮깁니다. 직접 만든 확장은 그대로):

## 6. 필요할 때 한 번 하는 설정
**내 설정 파일** `~/.pi/agent/bridge.json` 에 바꿀 항목만 적습니다 (메모장이나 VS Code 로 열기). 업데이트해도 그대로 남습니다.
- 항목은 맨 바깥 `{ }` 안에 적습니다 (`_예시` 안에 넣으면 적용되지 않음). 마지막 항목 뒤에는 쉼표를 넣지 않고, Windows 경로는 `/` 로 씁니다.
- **UTF-8** 로 저장합니다 (메모장의 'ANSI' 로 저장하면 한글이 깨져 오류가 남).

예:
```json
{
  "_설명": "(처음부터 있던 설명 줄은 그대로 두어도 됨)",
  "max_chars": 15000,
  "jupyter_url": "https://<kubeflow 주소>/notebook/<네임스페이스>/<노트북>/lab",
  "default_mode": "ask"
}
```

**고친 뒤 적용:**
1. 실행 중인 pi 를 모두 끕니다.
2. `curl -s -X POST http://127.0.0.1:8765/shutdown` (중계 서버 끄기)
3. `pi` 를 다시 실행하면 새 설정으로 켜집니다. `/doctor` 의 '내 설정' 줄에 적은 항목이 보입니다.

(`browser`, `auto_start_browser`, `jupyter_url`, `default_mode` 는 pi 를 실행할 때마다 읽고, `guard` 로 시작하는 항목과 `notify_after_seconds` 는 고치면 바로 적용됩니다.)

| 하고 싶은 것 | 항목 | 방법 |
|---|---|---|
| 새 대화를 열 때 덜 기다리기 | `max_chars` | pi 가 일하지 않을 때 `python ~/tools/pi/copilot/diag.py --input-limit` → 알려 주는 권장값을 적음 |
| Kubeflow 노트북 쓰기 | `jupyter_url` | 노트북의 JupyterLab 주소. 전용 창에서 Kubeflow 에 한 번 로그인. 확인: `python ~/tools/pi/copilot/diag.py --jupyter` |
| 늘 확인 모드(또는 계획 모드)로 시작 | `default_mode` | `"ask"` 또는 `"plan"` |
| 사용량 제한이 있는 계정 | `max_questions_per_minute` | `2` |
| pi 여러 개 동시에 | `max_tabs` | `2` 또는 `3` (pi 마다 Copilot 창을 따로 씀) |
| Edge 전용 창 쓰기 | `browser` | `"edge"` (Chrome 전용 창을 닫고, Edge 창에서 Copilot 에 다시 로그인) |
| 새 Copilot 모델 | `copilot_models` 와 `~/.pi/agent/models.json` | [README 4장](../README.md#4-모델-고르기) |
| Copilot 메뉴의 모델 이름이 바뀌었을 때 | `copilot_models` | 아래 '모델 이름이 바뀌었을 때' |
| 위험 명령 확인 조정 | `guard_allow`, `guard_patterns` | [README 10장](../README.md#10-설정) |

**팀 공유 폴더 (스킬·명령 같이 쓰기):**
1. 담당자가 공유 폴더에 `skills/<이름>/SKILL.md`, `prompts/<이름>.md` 를 두고, 팀원 모두 읽을 수 있게 권한을 줍니다.
   드라이브 문자가 사람마다 다르면 `//서버/공유/pi` 형식의 경로를 씁니다.
2. 팀원은 각자 pi 안에서 한 번: `/kit share //서버/공유/pi` (등록하면 Copilot 새 대화가 열려 다음 질문이 1~2분 걸림)

**모델 이름이 바뀌었을 때:** Copilot 이 메뉴의 모델 이름을 바꾸면 중계 서버가 고르지 못하고 그 대화는 '자동' 으로 답합니다
(중계 서버 로그에 `Copilot 모델 선택 실패`). 띄어쓰기·`-`·버전 끝의 `.0` 만 다른 이름(`GPT 6.0 Sol` 과 `GPT-6 Sol`)은 2026-10-06.1 부터 같은 이름으로 봅니다.
그 밖에 바뀌었으면 새 판을 기다리지 않고 내 설정 파일로 고칩니다.
1. pi 가 일하지 않을 때 메뉴의 이름을 확인합니다 (전용 창은 켜 둔 채로). 새 이름을 넣어 실행하면 메뉴 항목과 하위 메뉴(GPT ›, Claude ›)의 이름을 모두 보여 주고, 그 이름을 골라 봅니다:
   ```bash
   python ~/tools/pi/copilot/diag.py --model "GPT-6 Sol"
   ```
   마지막의 `'GPT-6 Sol' 고르기` 줄이 `OK` 면 그 이름을 씁니다. 이름 목록은 중계 서버 로그에도 있습니다: `grep "모델 선택 실패" ~/.pi/agent/copilot-relay.log | tail -1` 의 `있는 항목:`
2. 내 설정 파일에 'pi 모델 id → 새 이름' 을 적습니다. 바꿀 id 만 적으면 나머지는 저장소 값 그대로입니다 (id 는 [README 4장](../README.md#4-모델-고르기)의 표). 예: 기본 모델 `gpt-6.0-sol` 을 `GPT-6 Sol` 로
   ```bash
   PYTHONIOENCODING=utf-8 python - <<'EOF'
   import json, os
   p = os.path.expanduser("~/.pi/agent/bridge.json")
   cfg = json.load(open(p, encoding="utf-8-sig")) if os.path.exists(p) else {}
   cfg["copilot_model"] = "GPT-6 Sol"
   cfg.setdefault("copilot_models", {})["gpt-6.0-sol"] = "GPT-6 Sol"
   with open(p, "w", encoding="utf-8") as f:
       json.dump(cfg, f, ensure_ascii=False, indent=2)
   print(json.dumps(cfg, ensure_ascii=False, indent=2))
   EOF
   ```
   (메모장으로 고쳐도 됩니다: 맨 바깥 `{ }` 안에 `"copilot_models": {"gpt-6.0-sol": "GPT-6 Sol"}`. 다른 모델도 바뀌었으면 같은 표에 `"claude-opus": "새 이름"` 처럼 더함)
3. 위의 '고친 뒤 적용' 대로 다시 켭니다.
4. 확인: 질문 하나를 보낸 뒤 `grep "Copilot 모델" ~/.pi/agent/copilot-relay.log | tail -2` 에 `Copilot 모델 선택: 'GPT-6 Sol' 선택` 이 보이고, 전용 창의 모델 버튼에도 `GPT-6 Sol` 이 보이면 됩니다.

나중에 새 이름이 들어간 판으로 바꾼 뒤에는 이 항목을 지워도 되고, 그대로 두어도 됩니다 (같은 값).

## 7. 가끔 하는 정리
- `~/tools/pi.old`: 새 판이 며칠 잘 되면 `rm -rf ~/tools/pi.old` 로 지워도 됩니다 (그 뒤로는 zip 으로만 되돌림). 다음 업데이트 때도 자동으로 지워집니다.
- `~/.pi/agent/extensions.removed/`: 업데이트 때 치운 예전 확장입니다. 지워도 됩니다.
- 지침 파일의 `## 기억할 것` (`/remember` 로 쌓인 것): 많아지면 새 대화를 열 때 보내는 글이 길어지니 가끔 정리합니다.
- Copilot 대화 목록: pi 가 끝날 때 중계 서버가 만든 대화는 자동으로 지웁니다. 아래는 남으니 Copilot 화면 왼쪽 목록에서 직접 지웁니다.
  `diag.py --send` 의 시험 대화, `"delete_finished_chats": false` 일 때, 지우기에 세 번 실패한 대화(`/doctor` 의 `삭제 3번 실패 n`), 아주 예전 판이 만든 대화.
- 로그 `~/.pi/agent/copilot-relay.log`: 5MB 를 넘으면 pi 를 실행할 때 `copilot-relay.log.1` 로 돌려 둡니다. pi 를 끈 상태에서 지워도 됩니다.
- 노트북의 `~/pi-bridge` 폴더(실행 기록): pi 를 쓰지 않을 때 지워도 됩니다.
- 세션 기록 `~/.pi/agent/sessions/`: 필요 없는 대화 기록은 지워도 됩니다.

## 8. 문제가 생겼을 때
1. **화면 찍기:** pi 안에서 `/doctor` (pi 가 안 뜨면 `python ~/tools/pi/copilot/diag.py --report`. `python` 이 Microsoft Store 를 띄우면 pi 안의 `/doctor` 를 씀).
2. **흔한 해결:**

| 증상 | 해결 |
|---|---|
| `Connection error.` / `중계 서버에 연결할 수 없습니다` | pi 를 끄고 다시 실행 (중계 서버도 다시 켜짐) |
| `브라우저 원격 디버깅 포트(9222)에 연결할 수 없습니다` | 전용 창이 꺼진 것. pi 를 다시 실행하면 다시 띄움 |
| Copilot 로그인이 풀림 | 전용 창의 Copilot 탭에서 다시 로그인한 뒤 같은 요청을 다시 보냄 |
| JupyterLab 로그인이 풀림 (jupyter 모드) | 전용 창의 JupyterLab 탭에서 다시 로그인한 뒤 `/jupyter` |
| `429 Copilot 사용량 제한` | 잠시 기다렸다가 같은 요청을 다시 (자주 걸리면 6장의 `max_questions_per_minute`) |
| 전용 창의 모델 버튼이 고른 모델이 아니라 `자동` (로그에 `Copilot 모델 선택 실패`) | Copilot 이 모델 이름을 바꾼 것. 6장의 '모델 이름이 바뀌었을 때' |
| `입력창에 글자가 다 들어가지 않았습니다` / `Copilot 입력창이 글을 받지 않습니다` | `이어서 해줘` 로 다시 보냄 (2026-10-06.2 부터는 중계 서버가 기다렸다 보내므로 드묾). 반복되면 전용 창 화면과 `tail -30 ~/.pi/agent/copilot-relay.log` 를 보내 주세요 |
| 설정을 고쳤는데 그대로 | 6장의 '고친 뒤 적용' |
| 새 Git Bash 창에서 `pi: command not found` | `bash ~/tools/pi/install.sh pc` 를 다시 실행하고 창을 새로 엶 |

3. **보낼 것:** `/doctor` 화면 사진, 언제·무엇을 하다가·어떤 메시지가 났는지. 요청받으면 `~/.pi/agent/copilot-relay.log` 의 끝부분
   (실행한 명령과 파일 경로가 기록되니 보내기 전에 한 번 보고 보내 주세요).
- 전체 표: [README 11장](../README.md#11-문제-해결)

## 9. 지우기
더 쓰지 않을 때입니다. `~/.pi/agent` 에는 세션 기록(대화), 지침, 내 스킬도 있으니 필요하면 먼저 복사해 둡니다.

```bash
curl -s -X POST http://127.0.0.1:8765/shutdown

```

- 전용 브라우저 프로필 폴더를 탐색기에서 지웁니다: `%LOCALAPPDATA%\pi-copilot-chrome` (Edge 를 썼으면 `pi-copilot-edge`).
