# pi coding agent — 설치 안내

이 저장소는 **npm 없이 실행할 수 있게 구성한 pi 소스 모음**입니다. 설치 프로그램이나 실행파일(exe 등)은 없고, 스크립트와 JavaScript·Python 소스만 들어 있습니다.
외부에서 필요한 것은 **Node.js** 하나뿐이며, Node.js 가 없으면 PyPI 패키지 `nodejs-wheel-binaries` 로 준비합니다.
- Node 22.19 이상: pi 가 공식 지원하는 버전입니다.
- Node 20.15 이상 ~ 22.18: `compat/` 호환 레이어가 자동으로 적용됩니다.

## 구성
| 경로 | 내용 | 출처·라이선스 |
|---|---|---|
| `runtime/` | pi 0.87.1 실행 코드(`dist/bundle`), 테마/HTML 템플릿, 문서 | npm 공식 배포본 그대로, MIT (`LICENSE-pi`) |
| `runtime/node_modules/@earendil-works/chord` | pi 가 불러 쓰는 JS 라이브러리 | npm 공식 배포본 그대로, MIT |
| `runtime/node_modules/typebox` | pi 가 불러 쓰는 JS 라이브러리 | npm 공식 배포본 그대로, MIT |
| `runtime/node_modules/jiti` | pi 확장(.ts) 불러오기용 JS 라이브러리 | npm 공식 배포본 그대로, MIT |
| `bin/` | 실행기 (`pi`: Git Bash·Linux, `pi.cmd`: cmd·PowerShell), Node 탐색 | 자체 작성 |
| `compat/` | Node 20 호환 레이어, VS Code 내장 Node 실행 보조 | 자체 작성 |
| `install.sh`, `check-node.sh` | 설치·진단 스크립트 | 자체 작성 |
| `profiles/jupyter/`, `profiles/pc/` | 환경별 `~/.pi/agent` 설정 템플릿 | 자체 작성 |
| `copilot/` | (pc 전용) Copilot 웹 채팅 연동 중계기. 파이썬 표준 라이브러리만 사용 | 자체 작성 |
| `tests/` | 중계기 단위 테스트 | 자체 작성 |

바이너리(실행파일, .node, .wasm, 이미지)는 들어 있지 않습니다. 제3자 소스의 출처와 해시는 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md) 에 있습니다.

## 0. 저장소 풀기
압축 파일(`pi-agent-like-agent-main.zip`)을 풀어 원하는 위치에 둡니다. 아래 안내는 `~/tools/pi` 기준입니다.

**Kubeflow JupyterLab** — 파일 브라우저로 zip 을 홈에 업로드한 뒤 터미널에서:
```bash
mkdir -p ~/tools && python -m zipfile -e ~/pi-agent-like-agent-main.zip ~/tools/ && mv ~/tools/pi-agent-like-agent-main ~/tools/pi
```
반드시 **홈 디렉터리(PVC) 아래**에 두세요. 그래야 파드를 재시작해도 남습니다.

**업무 PC (Git Bash)**:
```bash
mkdir -p ~/tools && unzip -q pi-agent-like-agent-main.zip -d ~/tools/ && mv ~/tools/pi-agent-like-agent-main ~/tools/pi
```
이미 `~/tools/pi` 가 있으면 먼저 지우거나 이름을 바꾸세요. `~/.pi/agent` 의 설정은 따로 있으므로 지워지지 않습니다.

## 1. Node.js 확인
```bash
bash ~/tools/pi/check-node.sh
```
`결과: 사용 가능` 또는 `호환 모드로 사용 가능` 이면 2단계로 넘어갑니다.

Node 20.15 이상이 없으면, 아래 중 하나를 준비합니다. pi 실행기가 자동으로 찾습니다.

| 방법 | 명령 | 비고 |
|---|---|---|
| **Node.js 공식 바이너리 (PyPI)** | `pip install --user nodejs-wheel-binaries==24.19.0` | 권장. Linux 는 glibc 2.28 이상, Windows 는 x64 |
| Playwright 내장 Node (PyPI) | `pip install --user playwright` | **1.46 이상**(Node 20.16+). `playwright install`(브라우저 다운로드)은 필요 없음 |
| VS Code 데스크톱 내장 Node (Windows) | VS Code **1.93 이상** | 1.92 이하는 내장 Node 가 너무 낮음 (1.80 → Node 16) |

사내 pip 미러에 있는지 확인:
```bash
pip download --no-deps -d /tmp/pipchk nodejs-wheel-binaries==24.19.0
```

> **Kubeflow 에서는 반드시 `--user` 를 붙이세요.** `--user` 없이 설치하면 `/opt/conda`(컨테이너 이미지 영역)에 들어가 파드 재시작 시 사라집니다.
> `--user` 로 설치하면 홈(PVC)의 `~/.local` 에 남습니다.

**호환 모드(Node 20.x):** pi 는 공식적으로 Node 22.19 이상을 요구합니다. `compat/node20.mjs` 가 pi 가 쓰는 Node 22 전용 기능을 보충합니다.
- 보충하는 기능: `fs.globSync`, `Promise.withResolvers`, `process.getBuiltinModule`, `module.enableCompileCache`
- 기본 사용(read/write/edit/bash 도구, 대화, 세션)은 검증했지만 공식 지원 범위는 아닙니다.
- Node 22.19 이상을 쓸 수 있게 되면 자동으로 호환 레이어 없이 실행됩니다.

pi 실행기는 Node 를 다음 순서로 찾습니다. 22.19 이상을 먼저 고르고, 없으면 20.15 이상을 호환 모드로 씁니다.
1. `PI_NODE` 환경변수 (예: `export PI_NODE=/opt/node/bin/node`)
2. pip 패키지 `nodejs-wheel-binaries`, `playwright`(내장 Node)
3. PATH 의 `node`
4. Node 기본 설치 경로 (Windows: `C:\Program Files\nodejs`)
5. code-server 내장 node (`/usr/lib/code-server/lib/node`)
6. **(Windows) VS Code 계열 편집기 내장 Node**: VS Code, VS Code Insiders, Cursor, Windsurf, Antigravity

### Windows 에 Node 가 없고 VS Code 만 있는 경우
VS Code 데스크톱은 Node 를 내장하고 있습니다. `code` 명령도 내부적으로 이 방식을 씁니다.
pi 실행기가 이를 자동으로 찾아 `ELECTRON_RUN_AS_NODE=1` 로 실행하므로 별도 설치가 필요 없습니다.
- VS Code 내장 Node 버전 확인 (Git Bash):
  ```bash
  ELECTRON_RUN_AS_NODE=1 ~/AppData/Local/Programs/"Microsoft VS Code"/Code.exe -v
  ```
  - 22.19 이상이면 정식 모드, 20.15 이상이면 호환 모드로 실행됩니다.
  - **VS Code 1.92 이하는 내장 Node 가 20.15 미만이라 쓸 수 없습니다** (예: 1.80 → Node 16.17). 실행기가 자동으로 건너뜁니다.
  - 버전별 내장 Node: 1.93 → 20.15, 1.94 → 20.16, 1.96~1.97 → 20.18, 1.101 → 22.15
- **portable VS Code**(zip 압축 해제형)는 설치 위치가 정해져 있지 않아 자동으로 찾지 못합니다. 그 폴더 안의 `Code.exe` 경로를 한 번만 지정하세요 (cmd·Git Bash 어디서든):
  ```
  setx PI_NODE "C:\경로\VSCode-win32-x64-1.97.2\Code.exe"
  ```
  - PortableApps 형식(`VSCodePortable`)이면 `VSCodePortable.exe` 가 아니라 `App\VSCode\Code.exe` 를 지정합니다.
  - portable 의 `data` 폴더(설정·확장)는 pi 와 무관하며 건드리지 않습니다.
  새로 연 터미널부터 Git Bash·cmd·PowerShell 모두에 적용됩니다. 확인: `PI_DEBUG=1 pi --version`
- **대화형 화면(TUI)과 터미널 중계**: `Code.exe` 는 GUI 프로그램이라 터미널을 직접 쓰지 못합니다. 그래서 대화형으로 실행하면 실행기가 자동으로 **터미널 중계**(`bin/tty-relay.sh`, `compat/tty-relay.mjs`)를 씁니다.
  - 동작: 터미널을 raw 모드로 바꾸고, 키보드 입력과 화면 출력을 `cat` 으로 이어 줍니다. 창 크기는 0.4초마다 확인해 반영합니다.
  - 종료: `Ctrl+C` 두 번(0.5초 안) 또는 입력창이 비었을 때 `Ctrl+D`. 종료하면 터미널 설정이 원래대로 돌아옵니다.
  - 만약 화면이 깨진 채 끝나면 `reset` 또는 `stty sane` 을 입력하세요.
  - `pi -p` (한 번씩 묻기)는 중계 없이 바로 실행됩니다.

## 2. 설치
```bash
bash ~/tools/pi/install.sh jupyter     # Kubeflow JupyterLab 터미널 + 사내 vLLM
bash ~/tools/pi/install.sh pc          # 업무 PC Git Bash + Copilot 웹 채팅
# 새 터미널을 열고
pi --version
```
- `install.sh` 는 `profiles/<설정>/agent-template` 을 `~/.pi/agent` 에 복사합니다 (이미 있는 설정 파일은 그대로 둠).
- PATH 를 `~/.bashrc` 에 넣고, Linux 에서는 로그인 셸이 읽는 파일(`~/.bash_profile`·`~/.bash_login`·`~/.profile` 중 있는 것, 없으면 `~/.profile` 을 만듦)에도 한 줄 넣습니다.
  **JupyterLab 터미널은 로그인 셸이라 `~/.bashrc` 를 읽지 않기 때문입니다.** 설치한 그 터미널에서 바로 쓰려면 `export PATH="$HOME/tools/pi/bin:$PATH"`.
- pip 로 Node 를 설치한 경우, 그 Python 환경(conda env 등)이 터미널에서 활성화되어 있어야 찾을 수 있습니다.
  찾지 못하면 `python -c "import nodejs_wheel,os;print(os.path.dirname(nodejs_wheel.__file__))"` 로 경로를 확인한 뒤 `PI_NODE` 로 지정하세요.
- Windows cmd/PowerShell 에서는 `bin\pi.cmd` 를 사용합니다.

## 3. LLM 연결
| 설정 | 실행 위치 | LLM | 안내 |
|---|---|---|---|
| `jupyter` | Kubeflow JupyterLab 터미널 | 사내 vLLM (OpenAI 호환) | [vLLM-연결.md](vLLM-연결.md) |
| `pc` | 업무 PC 의 Git Bash | Copilot 웹 채팅 (브라우저) | [copilot/README-copilot.md](../copilot/README-copilot.md) |

- `pc` 설정(브리지 pi)은 명령을 PC 의 Git Bash 에서 실행하거나(`pi`), Kubeflow 노트북 안에서 실행할 수 있습니다(`pi --jupyter 폴더`).
- 다른 OpenAI 호환 API 를 쓰려면 `~/.pi/agent/models.json` 에 provider 를 추가하고,
  `settings.json` 의 `defaultProvider` / `defaultModel` 을 바꾸면 됩니다 (형식은 `runtime/docs/models.md`).

## 참고
- 어떤 Node 로 실행되는지 보려면: `PI_DEBUG=1 pi --version` (cmd 는 `set PI_DEBUG=1` 후 `pi.cmd --version`)
- 실행기는 `PI_OFFLINE=1`(자동 네트워크 활동 끔)과 `PI_SKIP_VERSION_CHECK=1`(최신 버전 확인 끔)을 설정합니다. 설정 템플릿은 `enableInstallTelemetry: false` 입니다.
- 기본 도구(read/bash/edit/write)는 추가 프로그램 없이 동작합니다.
- pi 시작 화면의 `Warning: fd not found ... / ripgrep not found ...` 는 무시해도 됩니다 (기본 도구는 이 둘 없이 동작).
- 선택 사항인 `--tools grep,find` 를 쓰려면 ripgrep 이 필요합니다: `pip install --user ripgrep==14.1.0`
  (fd 는 pip 로 제공되지 않으므로 find 도구는 쓸 수 없습니다.)
- 이미지 축소(photon wasm)와 클립보드 붙여넣기 같은 네이티브 기능은 빠져 있습니다. 텍스트 기반 코딩 작업에는 영향이 없습니다.
