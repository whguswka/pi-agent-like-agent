## 3. 동작 방식
- pi 는 사용자가 터미널에서 지시한 작업을 LLM 과 주고받으며 수행합니다. LLM 이 요청한 도구(파일 읽기·쓰기·수정, 셸 명령 실행)를 **사용자 계정 권한으로** 실행합니다. 이는 코딩 에이전트의 기본 기능입니다. <!-- api= - pi 는 사용자가 노트북 터미널에서 지시한 작업을 LLM 과 주고받으며 수행합니다. LLM 이 요청한 도구(파일 읽기·쓰기·수정, 셸 명령 실행)를 **노트북 안에서 사용자 계정 권한으로** 실행합니다. 이는 코딩 에이전트의 기본 기능입니다. -->
  - 되돌리기 어려운 작업(폴더 삭제, `git push`, `kubectl delete`, 패키지 제거, `sudo`, 작업 폴더 밖 파일 쓰기 등)은 실행 전에 사용자에게 확인을 받고, 거부하면 실행하지 않습니다 (확장 `guard.ts`).
  - **작업 기록 (2026-10-21, 확장 `memory.ts`):** 요청이 끝날 때마다 요청 글, 바꾼 파일 이름, 실행한 명령, 답의 앞부분을 작업 폴더별 파일(`~/.pi/agent/work-log/`, 사용자 홈)에 남기고, 같은 폴더에서 새 세션을 시작하면 그 요약(1200자 안)을 LLM 에 보내는 지침에 넣습니다. 이메일·전화번호·계좌번호 모양 번호는 빼고 남기고, 비밀번호·토큰으로 보이는 글은 남기지 않습니다. 사용자가 끌 수 있습니다(`/recall off`). 따로 네트워크에 접속하지 않습니다.
  - **설치된 라이브러리 설명 찾기 (2026-10-21, 확장 `kit.ts`):** LLM 이나 사용자가 요청하면 이미 설치된 Python 패키지를 불러와(import) 버전·설명 글을 읽고, 사용자 폴더(`~/pi-docs`)의 문서에서 맞는 줄을 찾아 그 결과를 LLM 에 보냅니다. 인터넷에 접속하지 않고 패키지를 설치하지 않습니다.
  - **작업 방식 배우기 (2026-10-20, 확장 `wiki.ts`):** LLM 위키를 켠 사용자가 쓰면, LLM 이 위키를 쓰면서 함께 적은 일하는 방식(최대 10줄·1200자)을 사용자 지침 파일(`~/.pi/agent/AGENTS.md`)의 정해진 부분에 자동으로 적습니다. 고치기 전 내용을 남기고 되돌릴 수 있으며(`/wiki lessons undo`), 끄거나 제안만 받을 수 있습니다(`/wiki lessons off`·`propose`).
  - **문서 규칙 (2026-10-22, 확장 `hooks.ts`):** 작업 폴더에 새 Markdown 문서가 생기면, 그 링크 한 줄을 프로젝트의 문서 목록 파일(`docs/INDEX.md`)에 확장이 직접 더합니다.
    목록 파일이 없으면 사용자에게 묻고 만듭니다. 한 요청에 새 문서가 많거나 이력·계획 문서가 겹치면 만들기 전에 사용자에게 묻고, 읽기는 막지 않습니다.
    `/hooks` 로 이 규칙과 사용자가 만든 확장을 켜고 끄며, 위험 명령 확인(`guard.ts`)이 꺼져 있으면 시작할 때와 상태 줄에 알립니다. 네트워크 사용 없음.
  - 사용자가 고르면 더 조심스럽게 쓸 수 있습니다 (확장 `modes.ts`): 계획 모드는 읽기만 하고 계획을 세워 사용자가 승인한 뒤에 실행하고, 확인 모드는 파일을 바꾸거나 명령을 실행할 때마다 바뀌는 내용을 보여 주고 확인을 받습니다. pi 가 고친 파일은 `/undo` 로 되돌릴 수 있습니다 (확장 `undo.ts`).
  <!-- api:바꾸기 3장-설정 -->
- `jupyter` 설정: JupyterLab 터미널에서 실행합니다. LLM 은 설정 파일에 적은 사내 vLLM 주소입니다.
- `pc` 설정: 업무 PC 에서 실행합니다. pi 의 LLM 요청은 PC 내부 중계기(127.0.0.1:8765)가 받아, 사용자가 직접 로그인해 둔 Chrome(또는 Edge) 전용 창의 Copilot 탭에 질문을 입력하고 답을 읽어 돌려줍니다. 브라우저는 전용 프로필과 원격 디버깅 포트(127.0.0.1:9222)로 실행합니다.
  - Copilot 화면의 모델 메뉴에서 사용자가 pi 에서 고른 모델을 선택합니다 (새 채팅마다 '자동' 으로 돌아가기 때문).
  - pi 세션이 끝나면 그 세션이 만든 Copilot 대화를 사용자 계정의 대화 목록에서 삭제합니다. 중계기가 만든 대화만 기록해 두고 그것만 지우며, 설정(`delete_finished_chats`)으로 끌 수 있습니다.
  - `pi --jupyter <폴더>` 로 실행하면, 사용자가 열어 둔 JupyterLab 탭을 통해 노트북 터미널(`pibridge`)에서 명령을 실행하고 Jupyter 파일 기능으로 파일을 읽고 씁니다. 노트북에는 아무것도 설치하지 않습니다.
  - 사용자가 pi 에서 사내AI 모델(`inhouse-sonnet`, `inhouse-gemma4`)을 고르면, 같은 중계기 코드를 사내AI 설정(`copilot/inhouse.json`)으로 띄운 두 번째 중계기(127.0.0.1:8766)가 같은 전용 창의 사내AI 탭(사내 서비스, 사용자 로그인)에 질문을 입력하고 답을 읽습니다.
    사내AI 화면의 안전모드·성능모드 단추를 사용자가 고른 모델에 맞게 누릅니다. 사내AI 대화 목록은 지우지 않습니다.
  - 중계기는 요청마다 걸린 시간, 글자 수, 다시 요청한 횟수, 오류 종류 같은 **횟수·시간 기록**을 PC 안의 파일(`~/.pi/agent/relay-events.jsonl`, 사내AI 는 `inhouse-events.jsonl`)에 남깁니다.
    요청·답의 내용, 파일 내용, 명령은 남기지 않으며, 어디로도 보내지 않습니다 (네트워크 접속 없음). 사용자가 `diag.py --limits` 로 요약을 봅니다. 설정(`collect_events`)으로 끌 수 있고 파일은 지워도 됩니다.
  - Copilot 에는 pi 가 다루는 그림(그래프 등)을 입력창에 붙여 함께 보냅니다 (2026-10-17, 설정 `send_images` 로 끔). 사내AI 에는 그림을 보내지 않습니다.
  - 사내AI 에는 1만 자가 넘는 메시지를 나눠 보내지 않고 글 파일(.txt)로 붙여 보냅니다 (2026-10-20, 설정 `attach_long_text`). 전화번호·카드번호 같은 개인정보 모양 글이 있으면 붙이지 않고 글로 나눠 보내, 사내AI 의 개인정보 확인을 거치게 합니다.
  - 사내AI 로 보내기 직전에 이메일 주소와 계좌번호 모양 번호를 `[이메일1]`·`[번호1]` 같은 표시로 바꾸고, 답에서 원래 값으로 되돌립니다 (2026-10-19·2026-10-20, 설정 `redact_emails`·`redact_numbers`). 원래 값과 표시의 짝은 중계기 메모리에만 두고 파일·로그에 남기지 않습니다.
    사내AI 의 개인정보 확인은 그대로 거치며, 막히면 다시 보내지 않고 멈춰 사용자에게 알립니다 (일부만 가려 보내거나 자동으로 다시 보내지 않음).
  - **화면 확인 스킬 (2026-10-22, `pc-screen`):** 사용자가 시킨 창 프로그램이 화면에 실제로 보이는지 확인할 때, LLM 이 지정한 창·영역만 찍어 작업 폴더에 PNG 로 저장합니다.
    그 그림을 열면 다른 그림처럼 Copilot 에 함께 보냅니다 (사내AI 에는 보내지 않음). 스킬 지침은 확인할 창·영역만 찍게 하고, 창 목록에는 다른 프로그램 창의 제목을 적지 않습니다.

## 6. 백신 검사 관련
pi 는 셸 명령을 실행하는 코딩 에이전트이고, 배포본은 여러 모듈을 하나로 묶고 압축(minify)한 JavaScript 입니다. 프로세스 실행 코드와 압축된 코드가 함께 있어, 일부 백신의 휴리스틱(행위 추정) 검사에서 의심 파일로 분류될 수 있습니다. 이 경우 5번 방법으로 공식 배포본과 같은 파일인지 확인해 주시기 바랍니다.
