# pi 빠른 시작 (한 장 요약)

Copilot 웹 채팅을 두뇌로 쓰는 코딩 에이전트입니다. Git Bash 에서 말로 시키면 파일을 읽고 고치고, 명령을 실행해 확인합니다.
자세한 설명은 [README](../README.md).

## 1. 설치 (처음 한 번, Git Bash 에서)
업무 PC 는 인터넷이 안 되므로, 인터넷 PC 에서 GitHub 의 **Code > Download ZIP** 으로 받은 zip 을 사내 반입 절차로 옮깁니다 ([수동 작업 절차](수동-작업-절차.md)).
**이미 설치되어 있으면**(`~/tools/pi` 가 있으면) 아래 세 줄은 실행하지 말고, 이 장 끝의 '새 판으로 바꿀 때' 명령만 실행합니다. 처음이면 zip 이 있는 폴더에서:
```bash
mkdir -p ~/tools && unzip -q pi-agent-like-agent-main.zip -d ~/tools/ && mv ~/tools/pi-agent-like-agent-main ~/tools/pi
bash ~/tools/pi/check-node.sh        # 마지막 줄이 '결과: 사용 가능' 또는 '결과: 호환 모드로 사용 가능' 이면 됨
bash ~/tools/pi/install.sh pc
```
**새 Git Bash 창**을 열고 작업 폴더에서 `pi` 를 실행합니다. 처음에는 Chrome 전용 창이 뜨니 거기서 **Copilot 에 로그인**합니다 (한 번만).
시작 화면의 `Warning: fd not found ...`, `Warning: ripgrep not found ...` 두 줄은 늘 나오는 것이니 무시합니다 (쓰지 않는 검색 도구 안내).
- 새 판으로 바꿀 때 (pi 를 모두 끈 뒤, 예전 판도 같음. 받은 zip 이름이 다르면 `Z=` 뒤를 바꿈):
  ```bash
  cd ~ && Z=~/Downloads/pi-agent-like-agent-main.zip
  unzip -o -j -q "$Z" '*/update.sh' -d ~/tools && bash ~/tools/update.sh "$Z"
  ```
  자세한 것과 되돌리기: [수동 작업 절차 3·5장](수동-작업-절차.md#3-새-판으로-바꾸기)

## 2. 매일 쓰기
```bash
cd ~/work/내프로젝트 && pi          # 시작 (pi -c: 이 폴더의 지난 대화 이어서)
```
할 일을 그대로 적고 `Enter`. 예: `@src/main.py 의 오류 처리를 고치고 테스트까지 돌려줘`
- 멈추기 `Esc` · 줄 바꾸기 `Shift+Enter` · 끝내기 `/quit` (`/exit` 도 됨)
- Chrome 전용 창은 최소화해도 되지만 **닫지 말고, 그 창에서 직접 대화하지 마세요.**

## 3. 자주 쓰는 명령
| 명령 | 하는 일 |
|---|---|
| `/plan` | **계획부터**: 읽기만 하고 계획을 세움 → "이 계획대로 진행할까요?" 에서 고르면 진행 |
| `/mode ask` · `/mode auto` | 바꿀 때마다 확인하며 진행 · 묻지 않고 진행 (기본) |
| `@파일` | `@` 를 치고 파일을 고름. 보낼 때 파일 내용이 함께 가서 빠름 |
| `/undo` | pi 가 고친 파일을 요청 전으로 되돌림 (`/undo 2`: 두 요청) |
| `/remember <내용>` | 앞으로도 지킬 것을 지침(AGENTS.md)에 적음. 예: `/remember 커밋 메시지는 한국어로` |
| `/handoff` | 한 일·남은 일을 NOTES.md 에 정리 → 다음 날 `pi -c` 로 이어 가기 |
| `/review` · `/test` · `/commit` · `/explain 파일` | 변경 검토 · 테스트 돌리고 고치기 · 커밋 · 코드 설명 |
| `/skill:이름` | 스킬 쓰기 (보고서 `korean-report`, 데이터 분석 `data-analysis`, 디버깅 `debugging` 등) |
| `/jupyter 폴더` · `/local` | 명령·파일 작업을 Kubeflow 노트북에서 · 다시 PC 에서 |
| `/upload` · `/download` | PC ↔ 노트북 파일·폴더 주고받기 |
| `/model` | 모델 고르기 (`Ctrl+P` 다음 모델). 사내AI: `inhouse-gemma4`(안전모드) · `inhouse-sonnet`(성능모드, 개인정보·중요정보 금지) |
| `/kit` · `/doctor` | 빠른 도움말 · 상태 요약 |

## 4. 작업 모드 세 가지 (상태 줄에 보임)
| 모드 | 언제 | 하는 일 |
|---|---|---|
| **계획** (`/plan`) | 큰 작업, 처음 보는 코드 | 파일은 읽기만. 계획을 보고 승인하면 진행하고, 진행 중 단계 목록이 체크됨 |
| **확인** (`/mode ask`) | 중요한 저장소 | 파일을 바꾸거나 명령을 실행하기 전에 바뀌는 줄(`-`/`+`)을 보여 주고 물음 |
| **자동** (`/mode auto`) | 평소 | 묻지 않고 진행. 폴더 지우기·`git push` 같은 위험한 명령만 물음 |

잘못 고쳤으면 `/undo`. 셸 명령으로 바뀐 파일은 되돌리지 못하니 중요한 폴더는 git 으로 관리하세요.

## 5. 막히면
- 사용법은 **`/kit`**. 문제가 생기면 **`/doctor`** 화면을 찍어 보내 주세요 (pi 밖에서는 `python ~/tools/pi/copilot/diag.py --report`).
- 업데이트·되돌리기·설정 같은 직접 하는 일: [수동 작업 절차](수동-작업-절차.md)
- 느리다: Copilot 왕복이 한 번에 7~20초입니다. `@파일` 로 파일을 붙이고, 요청을 구체적으로 적으면 왕복이 줄어듭니다.
- 쓰지 말 것: `/share` (대화를 외부에 올림). 평소에 피할 것: `/compact`·`/fork`·`/clone`·`/tree` (Copilot 새 대화가 열려 느림. `/compact` 는 [요약 점검](수동-작업-절차.md#4-2-요약-점검) 때 한 번).
