# 스킬 만들기

스킬은 특정 작업을 할 때만 읽는 지침 폴더다. pi 는 평소에는 스킬의 이름과 설명(description)만 보고, 작업이 설명과 맞을 때 SKILL.md 를 읽는다.

## 순서
1. 무엇을 할 때 쓰는 스킬인지, 어떤 절차·양식·주의할 점이 들어가야 하는지 확인한다 (이미 대화에 나왔으면 그것을 쓴다).
2. 위치를 정한다.
   - 모든 프로젝트에서 쓸 것: `~/.pi/agent/skills/<이름>/SKILL.md` (작업 폴더 밖이라 쓰기 전에 확인 창이 뜬다)
   - 이 프로젝트에서만 쓸 것: 작업 폴더의 `.pi/skills/<이름>/SKILL.md` (pi 가 다음에 시작할 때 이 폴더를 믿을지 묻는다)
3. 아래 형식으로 SKILL.md 를 쓴다. 긴 참고 자료나 양식은 같은 폴더의 다른 파일(예: `template.md`)로 나누고, SKILL.md 에서 그 파일 이름을 적어 필요할 때 읽게 한다.
4. 다 만들면 `/reload` 를 입력하라고 알리고, `/skill:<이름>` 으로 바로 써 볼 수 있다고 안내한다.

## 형식
```markdown
---
name: weekly-sales
description: 주간 매출 엑셀을 정리할 때 사용. 지점별 합계와 전주 대비 증감을 계산해 요약 시트를 만든다.
---
# 주간 매출 정리
1. ...
2. ...
```

## 규칙
- name: 영문 소문자·숫자·하이픈(-)만, 64자 이내, 폴더 이름과 같게 (예: weekly-report, sql-style).
- description: 1024자 이내. "무엇을 하는지" 와 "언제 쓰는지" 를 모두 적는다. LLM 은 이 설명만 보고 스킬을 고르므로 "○○ 도와주는 스킬" 처럼 막연하게 쓰지 않는다.
- 본문: 명령형으로, 꼭 필요한 것만 번호 순서로 쓴다. 이미 아는 일반 지식은 쓰지 않는다.
- 다른 파일은 스킬 폴더 기준 상대 경로로 가리킨다.
- 비밀번호·토큰 같은 비밀은 넣지 않는다.
- 스크립트를 넣을 수는 있지만 jupyter 모드에서는 명령이 노트북에서 실행되므로 PC 의 스크립트를 쓸 수 없다. 짧은 코드는 본문에 예시로 적는 편이 낫다.
