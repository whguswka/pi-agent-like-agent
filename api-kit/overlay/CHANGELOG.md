위키의 있는 페이지를 덧붙이기·고치기로 고치고, 위키를 쓸 때마다 무엇을 쓰고 배웠는지 대화창에 보여 줍니다. 바탕: pi-agent-like-agent 2026-10-21.1.
- **위키: 있는 페이지는 덧붙이기·고치기로** ([README 5장 'LLM 위키'](README.md#llm-위키-wiki)):
  - 모델이 있는 페이지를 고칠 때 페이지 전체를 다시 써서, 읽지 않은 부분(위키 읽기는 5500자까지)이나 검색에서 못 본 부분이 지워지는 일이 이어졌습니다 (사용자 보고).
  - `wiki_write` 로 페이지 전체를 보내지 않고 바꿀 곳만 보냅니다. 도구 수는 그대로이고 새 페이지와 한 번에 보낼 수 있습니다.
    - `=== 덧붙이기 <페이지>`: 페이지 끝에 붙입니다. 뒤에 `## 절 제목` 을 붙이면 그 절 끝에 (없는 절이면 만듦). 근거 원본은 페이지의 `sources` 에 더합니다.
    - `=== 고치기 <페이지>`: `<<<<<<< 찾기` / `=======` / `>>>>>>> 바꾸기` 블록으로 찾은 한 곳만 바꿉니다. 못 찾거나 여러 곳에 맞으면 그 페이지는 그대로 두고 모델에게 알립니다.
  - 통째로 다시 써서 원래 내용이 많이 빠지면(원래 줄의 30% 넘게 빠지고 본문이 70% 아래로 짧아짐) 쓰지 않고, 모델에게 덧붙이기·고치기를 쓰라고 알립니다. 페이지를 나누는 등 일부러 줄일 때는 `=== 다시쓰기`.
  - llm-wiki 스킬, 위키를 켰을 때의 지침 줄, 새 위키의 `WIKI.md` 에 같은 규칙을 적었습니다. 이미 만든 위키의 `WIKI.md` 는 바뀌지 않습니다 (원하면 '페이지 규칙' 에 '있는 페이지는 통째로 다시 쓰지 않고 덧붙이거나 고친다' 를 더하세요).
- **위키를 쓸 때마다 대화창에 `[위키 '이름']` 항목**:
  - 무엇을 썼는지(`새로`·`덧붙임`·`고침`·`다시 씀` 과 페이지)와 작업 방식에서 무엇을 배웠는지가 나옵니다: `+` 내 지침에 더한 줄(전체), `=` 이미 있어 횟수만 올린 줄, `-` 한도로 뺀 줄, 제안만이면 `?`.
  - 배울 때(켜짐·제안만)인데 모델이 '작업 방식' 을 적지 않았으면 `작업 방식: 이번에 배운 것 없음` 이 나와, 배우기가 도는지 모델이 적지 않는지 나눠 볼 수 있습니다.
  - 전에는 흐린 알림 한 줄(줄을 더했을 때만)이었고 세션을 다시 열면 없어졌습니다. 이제 세션에 남아 다시 열어도 보입니다. 모델에게는 가지 않습니다.
- 작업 방식 '제안만' 일 때 작업 방식 줄을 하나씩 따로 제안으로 모읍니다 (`/wiki lessons` 의 제안 수가 줄 수와 같음).
- llm-wiki 스킬의 작업 방식 예시의 분류를 `runbook`(운영 절차)으로 고쳤습니다 (전에는 기본 분류에 없는 `procedure`).
- Releases 의 가벼운 zip 으로 바꿀 수 있습니다 (pi 본체는 그대로).
- 확인한 환경: 개발 PC 에서 위키 시험(단위)과 가짜 모델로 돌린 pi 화면(덧붙이기, 다시 쓰기 거절, 항목, 세션 다시 열기)을 돌렸습니다. Kubeflow 노트북에서는 돌려 보지 않았습니다.
- 할 일: 없음. 다시 쓰기로 지워진 위키 내용은 위키 폴더의 `.history/<날짜>/` 에 고치기 전 페이지로 남아 있습니다.

    pi 가 내 지침(`~/.pi/agent/AGENTS.md`)의 '작업 방식' 부분에 적습니다. 도구를 한 번 더 부르지 않습니다.
  - 10줄·1200자까지입니다. 같은 줄은 횟수만 올리고, 넘치면 덜 쓰이고 오래된 줄부터 `~/.pi/agent/lessons/archive.md` 로 뺍니다. 끝의 날짜 표시를 지운 줄은 pi 가 건드리지 않습니다.
  - 고칠 때마다 알림이 뜨고 고치기 전 지침은 `~/.pi/agent/lessons/` 에 남습니다. 보기 `/wiki lessons`, 되돌리기 `/wiki lessons undo`. 반영은 다음 세션부터입니다.

  - `~/.pi/agent/wiki.json` 의 `"lessons"`: `auto` | `propose` | `off`. 없으면 `"auto"` 가 `write` 일 때 `auto`, `ask` 일 때 `propose`, 그 밖은 `off`.

    실제 모델이 '작업 방식' 을 잘 적는지는 아직 확인하지 못했습니다.
- Releases 의 가벼운 zip 으로 바꿀 수 있습니다 (pi 본체는 그대로).
- 확인한 환경: 개발 PC 에서 위키 시험(단위, 가짜 모델로 돌린 pi, 폴더째 반영)과 설치·업데이트를 돌렸습니다. Kubeflow 노트북에서는 돌려 보지 않았습니다.
