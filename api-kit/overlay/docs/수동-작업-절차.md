사용법 전체는 [README](../README.md), 한 장 요약은 [빠른 시작](빠른시작.md) 에 있습니다.

## 1. 반입과 배포 (배포 담당)
1. 인터넷 PC 에서 [GitHub 저장소](https://github.com/whguswka/pi-agent-like-agent-api) 의 **Code > Download ZIP** 으로 `pi-agent-like-agent-api-main.zip` 을 받습니다.
   - 판 번호는 저장소 첫 화면 파일 목록의 `VERSION` 에 있습니다 (예: `2026-10-14.2`). 바뀐 점과 바꾼 뒤 할 일은 [CHANGELOG.md](../CHANGELOG.md).
   - 예전 판이 필요하면(되돌리기 등) 저장소의 **Tags** 에서 그 판(`v<판 번호>`)의 zip 을 받습니다. 이름만 다를 뿐 같은 방법으로 깝니다.
2. 사내 반입 절차로 zip 을 업무망에 넘깁니다. 처음이거나 보안 검토가 필요하면 [반입 검토 자료](반입-검토-요청서.md)를 함께 냅니다.
   - 전송 시스템의 백신이 파일을 막으면 **파일을 고치거나 압축 방식을 바꾸지 말고** 보안 담당에게 검토를 요청합니다
     (pi 실행 코드는 압축(minify)된 JavaScript 라 오탐이 날 수 있습니다. 검토 자료 5장에 파일 해시 목록이 있습니다).
3. 받은 zip 을 쓸 사람이 가져갈 수 있는 곳(공유 폴더 등)에 둡니다. **이전 판 zip 도 지우지 말고** 함께 두면 되돌릴 때 씁니다 (5장).
4. 알립니다: zip 위치, 바꾸는 명령(3장), 바뀐 점과 할 일([CHANGELOG.md](../CHANGELOG.md) 의 그 판).
   처음 쓰는 사람에게는 [빠른 시작](빠른시작.md)과 **LLM 서버 주소·모델 이름** (2장의 3에서 씀).

## 2. 처음 설치
준비물 ([README 1장](../README.md#1-준비물)): 터미널(업무 PC 는 Git Bash), VS Code 1.93 이상(또는 Node 20.15 이상), LLM 서버 주소와 모델 이름.

1. zip 을 가져옵니다 (예: `~/Downloads`). 이름이 `pi-agent-like-agent-api-main (1).zip` 처럼 바뀌었으면 아래 명령의 이름도 바꿉니다.
   이미 `~/tools/pi` 가 있으면 설치하지 말고 3장으로 갑니다.
2. 풀고 설치합니다. 업무 PC (Git Bash):
   ```bash
   cd ~/Downloads
   mkdir -p ~/tools && unzip -q pi-agent-like-agent-api-main.zip -d ~/tools/ && mv ~/tools/pi-agent-like-agent-api-main ~/tools/pi
   bash ~/tools/pi/check-node.sh
   bash ~/tools/pi/install.sh pc
   ```
   Linux (Kubeflow JupyterLab: zip 을 파일 브라우저로 홈에 올린 뒤):
   ```bash
   mkdir -p ~/tools && python -m zipfile -e ~/pi-agent-like-agent-api-main.zip ~/tools/ && mv ~/tools/pi-agent-like-agent-api-main ~/tools/pi
   bash ~/tools/pi/check-node.sh
   bash ~/tools/pi/install.sh jupyter
   ```
   - `check-node.sh` 의 마지막 줄이 `결과: 사용 가능` 또는 `결과: 호환 모드로 사용 가능` 이면 됩니다.
     `결과: 사용 가능한 Node 없음` 이면 [README 2-2](../README.md#2-2-nodejs-확인) 대로 준비한 뒤 `install.sh` 를 다시 실행합니다.
3. LLM 서버를 적습니다: `~/.pi/agent/models.json` 의 주소·모델 이름, `settings.json` 의 `defaultModel` ([README 2-4](../README.md#2-4-llm-연결), [API 연결](API-연결.md)).
4. 터미널을 **새로** 열고 `pi --version` (판 번호가 나오면 설치된 것), 이어서 연결 확인:
   ```bash
   cd ~ && pi -p "bash 로 echo hello 를 실행하고 결과를 알려줘"
   ```
5. 작업 폴더에서 `pi` 를 실행하고 `hello.py 를 만들어서 hello 를 출력하고 실행해줘` → 파일이 생기고 결과가 나오면 끝입니다.
   시작 화면의 `Warning: fd not found ...`, `Warning: ripgrep not found ...` 두 줄은 늘 나오는 것이니 무시합니다.
6. 안 되면 8장.

## 3. 새 판으로 바꾸기
지금 판을 확인합니다:
```bash
cat ~/tools/pi/VERSION
```

### 3-1. 바꾸기
1. 실행 중인 pi 를 모두 끕니다 (`/quit`). `~/tools/pi` 를 연 탐색기·터미널·편집기도 닫습니다.
2. 받은 zip 의 위치·이름을 `Z=` 뒤에 적고 실행합니다:
   ```bash
   cd ~
   Z=~/Downloads/pi-agent-like-agent-api-main.zip
   unzip -o -j -q "$Z" '*/update.sh' -d ~/tools && bash ~/tools/update.sh "$Z"
   ```
   - 새 판의 `update.sh` 만 꺼내 `~/tools/update.sh` 에 두고 실행합니다. 옆의 `~/tools/pi` 를 새 판으로 바꾸고, 끝나면 꺼낸 파일은 지웁니다.
   - `bash ~/tools/pi/update.sh "$Z"` 로 해도 같습니다. `unzip` 이 없는 곳(Kubeflow 등)은 이쪽으로 합니다 (Python 으로 풂).
3. 마지막에 `[update] 완료: <지금 판> -> <새 판>` 이 나오면 4장으로 갑니다.
   바로 위의 `[update] 이 판에서 바뀐 점` 에 '할 일' 이 있으면 그것도 합니다 (전체는 `~/tools/pi/CHANGELOG.md`).

| 메시지 | 할 일 |
|---|---|
| `zip 파일이 없습니다` | `Z=` 뒤의 이름과 위치를 확인 (`ls ~/Downloads/*.zip` 으로 받은 파일 이름을 볼 수 있음. 이름에 공백이 있으면 `Z="$HOME/Downloads/pi-agent-like-agent-api-main (1).zip"` 처럼 따옴표) |
| `pi-agent-like-agent-api 저장소의 zip 이 아닙니다` | 이 저장소(pi-agent-like-agent-api)의 zip 인지 확인 |
| `이미 같은 판(...)입니다` | 받은 zip 이 새 판인지 확인 (브라우저가 `(1)` 을 붙여 저장한 새 파일일 수 있음). 같은 판을 다시 깔려면 끝에 `--force` |
| `지금 폴더의 이름을 바꾸지 못했습니다 (사용 중)` | pi, `~/tools/pi` 를 연 탐색기·터미널·VS Code 를 닫고 다시. 아무것도 바뀌지 않은 상태입니다 |
| `지난번 이전 판 폴더(...pi.old)를 지우지 못했습니다` | `~/tools/pi.old` 를 연 창을 닫고 다시 |
| `install.sh 가 실패했습니다` | 화면을 찍어 보내 주세요. 이전 판은 `~/tools/pi.old` 에 있습니다 (5장) |
| `치움: .../extensions/... (이 판에는 없는 확장 -> extensions.removed/)` | 정상. 새 판에서 빠진 확장을 옮겨 둔 것 |

### 3-2. update.sh 가 안 될 때 (손으로)
3-1 이 어떤 이유로든 안 되면 같은 일을 손으로 합니다. **한 줄로** 실행해야 중간에 실패할 때 거기서 멈춥니다 (Linux 는 끝의 `pc` 를 `jupyter` 로).
```bash
cd ~
Z=~/Downloads/pi-agent-like-agent-api-main.zip
rm -rf ~/tools/pi.old ~/tools/pi-agent-like-agent-api-main && mv ~/tools/pi ~/tools/pi.old && unzip -q "$Z" -d ~/tools/ && mv ~/tools/pi-agent-like-agent-api-main ~/tools/pi && bash ~/tools/pi/install.sh pc && cat ~/tools/pi/VERSION
```
- `unzip` 이 없으면 `unzip -q "$Z" -d ~/tools/` 대신 `python -m zipfile -e "$Z" ~/tools/`.
- 마지막에 새 판 번호가 나오면 된 것입니다.
- 도중에 멈췄는데 `~/tools/pi` 가 없고 `~/tools/pi.old` 만 있으면 `mv ~/tools/pi.old ~/tools/pi` 로 원래대로 돌립니다.

## 4. 바꾼 뒤 점검
새 판으로 바꿀 때마다 합니다 (5분).
1. 터미널을 새로 열고 작업 폴더에서 `pi` 를 실행합니다.
2. `/doctor` 를 칩니다. 맨 위 줄의 판 번호가 새 판이어야 합니다.
3. 새 기능을 한 번씩 써 봅니다.

| 해 볼 것 | 보여야 할 것 |
|---|---|
| `/kit` | 입력창 위 도움말에 `작업 /plan ...`, `@ 파일 고르기` 줄 |
| `/plan` 뒤에 `hello.txt 에 오늘 날짜를 적어 줘` | 상태 줄 `계획 모드 · 읽기만` → 번호 붙은 계획 → `이 계획대로 진행할까요?` 선택 창 |
| 선택 창에서 `진행 (확인: 바꿀 때마다 확인)` | 파일을 만들기 전에 `새 파일: hello.txt` 확인 창, 입력창 위에 `계획 진행` 목록 |
| `/mode auto` | 상태 줄의 모드 표시가 사라짐 |
| 입력창에 `@` | 작업 폴더의 파일 목록 (`@hel` 처럼 더 치면 좁혀짐, `Tab` 으로 고름) |
| `/undo` | `되돌릴까요?` → 방금 만든 `hello.txt` 가 지워짐 |
| `/remember 답은 짧게` | `어디에 기억할까요?` → 고르면 `기억했습니다` |

4. 이상하면 그 화면을 찍어 보내 주세요 (8장). 진행 선택 창이 뜨지 않으면 모델이 번호 붙은 계획을 쓰지 않은 것입니다 (모델에 따라 다름). 그 답 화면을 함께 보내 주세요.

## 5. 이전 판으로 되돌리기
새 판에 문제가 있으면 이전 판으로 돌아갑니다. `~/tools/pi.old` 에는 **바로 앞 판 하나만** 남습니다 (다음 업데이트 때 지워짐). 이전 판 zip 을 보관해 두면 언제든 되돌릴 수 있습니다 (없으면 GitHub 의 Tags 에서 그 판의 zip 을 받아 반입).

### 5-1. 이전 판 zip 이 있으면
```bash
cd ~
bash ~/tools/pi/update.sh ~/Downloads/<이전 판 zip>
```
- `참고: 지금 판보다 예전 판입니다` 가 나오고 그 판으로 바뀝니다. 지금 판은 `~/tools/pi.old` 로 남고, 그 판에 없는 확장은 치웁니다.

### 5-2. zip 이 없으면 (`~/tools/pi.old` 로)
1. 실행 중인 pi 를 모두 끕니다.
2. 아래를 실행합니다 (Linux 는 첫 줄 끝의 `pc` 를 `jupyter` 로). 둘째 줄은 지금 판에만 있던 키트 확장을 `extensions.removed` 로 옮깁니다 (직접 만든 확장은 그대로).
   ```bash
   cd ~ && rm -rf ~/tools/pi.new && mv ~/tools/pi ~/tools/pi.new && mv ~/tools/pi.old ~/tools/pi && bash ~/tools/pi/install.sh pc
   cd ~/.pi/agent/extensions && for f in $(cd ~/tools/pi.new/profiles/common/agent-template/extensions && find . -name '*.ts' | sed 's#^\./##'); do [ -e "$f" ] && [ ! -e ~/tools/pi/profiles/common/agent-template/extensions/"$f" ] && mkdir -p "../extensions.removed/$(dirname "$f")" && mv "$f" "../extensions.removed/$f" && echo "치움: $f"; done; cd ~
   ```
3. 나중에 다시 새 판으로 가려면: `rm -rf ~/tools/pi.old && mv ~/tools/pi ~/tools/pi.old && mv ~/tools/pi.new ~/tools/pi && bash ~/tools/pi/install.sh pc`

- 설정(내 설정 파일, `models.json`, 지침, 스킬, 세션 기록)은 되돌려도 그대로입니다.

## 6. 필요할 때 한 번 하는 설정
**내 설정 파일** `~/.pi/agent/bridge.json` 에 바꿀 항목만 적습니다 (메모장이나 VS Code 로 열기). 업데이트해도 그대로 남습니다.
- 항목은 맨 바깥 `{ }` 안에 적습니다 (`_예시` 안에 넣으면 적용되지 않음). 마지막 항목 뒤에는 쉼표를 넣지 않고, Windows 경로는 `/` 로 씁니다.
- **UTF-8** 로 저장합니다 (메모장의 'ANSI' 로 저장하면 한글이 깨짐).

예:
```json
{
  "_설명": "(처음부터 있던 설명 줄은 그대로 두어도 됨)",
  "default_mode": "ask",
  "guard_allow": ["^git push origin feature/"]
}
```

| 하고 싶은 것 | 항목 | 방법 |
|---|---|---|
| 늘 확인 모드(또는 계획 모드)로 시작 | `default_mode` | `"ask"` 또는 `"plan"` (pi 를 다시 시작할 때 적용) |
| 묻지 않을 명령 | `guard_allow` | 정규식 목록 (고치면 바로 적용) |
| 더 물어볼 명령 | `guard_patterns` | 정규식 목록 (고치면 바로 적용) |
| 작업 끝 알림 시간 | `notify_after_seconds` | 초 (0 이면 끔) |
| 모델 추가·바꾸기 | `~/.pi/agent/models.json` | [API 연결 2·5장](API-연결.md#5-모델서버-여러-개). pi 안에서 `/model` 을 열면 다시 읽음 |
| 키를 파일에 적지 않기 | `models.json` 의 `apiKey` | `"$VLLM_API_KEY"` 처럼 환경변수 이름, `~/.bashrc` 에 `export VLLM_API_KEY=...` |

**팀 공유 폴더 (스킬·명령 같이 쓰기):**
1. 담당자가 공유 폴더에 `skills/<이름>/SKILL.md`, `prompts/<이름>.md` 를 두고, 팀원 모두 읽을 수 있게 권한을 줍니다.
   드라이브 문자가 사람마다 다르면 `//서버/공유/pi` 형식의 경로를 씁니다.
2. 팀원은 각자 pi 안에서 한 번: `/kit share //서버/공유/pi`

## 7. 가끔 하는 정리
- `~/tools/pi.old`: 새 판이 며칠 잘 되면 `rm -rf ~/tools/pi.old` 로 지워도 됩니다 (그 뒤로는 zip 으로만 되돌림). 다음 업데이트 때도 자동으로 지워집니다.
- `~/.pi/agent/extensions.removed/`: 업데이트 때 치운 예전 확장입니다. 지워도 됩니다.
- 지침 파일의 `## 기억할 것` (`/remember` 로 쌓인 것): 많아지면 요청마다 보내는 지침이 길어지니 가끔 정리합니다.
- 세션 기록 `~/.pi/agent/sessions/`: 필요 없는 대화 기록은 지워도 됩니다.
- LLM 위키의 `.history/`: 고치기 전 페이지입니다. 오래된 것은 지워도 됩니다.

## 8. 문제가 생겼을 때
1. **화면 찍기:** pi 안에서 `/doctor`, 그리고 오류 메시지가 보이는 화면.
2. **흔한 해결:**

| 증상 | 해결 |
|---|---|
| `Connection error.` / `401` / `404` / 길이 초과 | [API 연결 7장](API-연결.md#7-자주-나는-오류) (먼저 `curl -s http://주소:8000/v1/models` 가 되는지) |
| 명령을 실행하지 않고 글로만 답함 | 서버의 도구 호출 설정 ([API 연결 4장](API-연결.md#4-도구-호출tool-calling이-켜져-있어야-합니다)) |
| 설정을 고쳤는데 그대로 | JSON 형식(쉼표·따옴표) 확인. `models.json` 은 `/model` 을 열 때, `settings.json`·`default_mode` 는 pi 를 다시 시작할 때 읽음 |
| 새 터미널에서 `pi: command not found` | `bash ~/tools/pi/install.sh pc` (Linux 는 `jupyter`) 를 다시 실행하고 터미널을 새로 엶 |

3. **보낼 것:** `/doctor` 화면 사진, 언제·무엇을 하다가·어떤 메시지가 났는지.
   세션 기록(`~/.pi/agent/sessions/`)에는 읽은 파일 내용과 명령 결과가 들어 있으니, 요청받아 보낼 때는 한 번 보고 보내 주세요.

## 9. 지우기
더 쓰지 않을 때입니다. `~/.pi/agent` 에는 세션 기록(대화), 지침, 내 스킬, `models.json` 도 있으니 필요하면 먼저 복사해 둡니다.
```bash
rm -rf ~/tools/pi ~/tools/pi.old ~/.pi/agent
```
- `~/.bashrc` (있으면 `~/.bash_profile` 이나 `~/.profile` 도) 에서 `.../tools/pi/bin:$PATH` 가 든 `export PATH=...` 줄을 지웁니다.
