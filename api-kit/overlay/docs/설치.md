# pi coding agent — 설치 안내

> 설치하고 쓰는 방법은 저장소 첫 페이지 [README](../README.md) 에 모두 있습니다.
> 이 문서는 Node.js 준비(code-server 내장 Node, 호환 모드), Kubeflow 노트북에 설치할 때의 주의 사항 같은 세부 내용입니다.

이 저장소는 **npm 없이 실행할 수 있게 구성한 pi 소스 모음**입니다. 설치 프로그램이나 실행파일은 없고, 스크립트와 JavaScript 소스만 들어 있습니다.
외부에서 필요한 것은 **Node.js** 하나뿐이며, code-server 노트북에는 보통 이미 들어 있습니다. 없으면 PyPI 패키지 `nodejs-wheel-binaries` 로 준비합니다.
- Node 22.19 이상: pi 가 공식 지원하는 버전입니다.
- Node 20.15 이상 ~ 22.18: `compat/` 호환 레이어가 자동으로 적용됩니다 (code-server 4.93 의 Node 20.15 가 여기에 해당).

## 구성
| 경로 | 내용 | 출처·라이선스 |
|---|---|---|
| `runtime/` | pi 0.87.1 실행 코드(`dist/bundle`), 테마/HTML 템플릿, 문서 | npm 공식 배포본 그대로, MIT (`LICENSE-pi`) |
| `runtime/node_modules/@earendil-works/chord` | pi 가 불러 쓰는 JS 라이브러리 | npm 공식 배포본 그대로, MIT |
| `runtime/node_modules/typebox` | pi 가 불러 쓰는 JS 라이브러리 | npm 공식 배포본 그대로, MIT |
| `runtime/node_modules/jiti` | pi 확장(.ts) 불러오기용 JS 라이브러리 | npm 공식 배포본 그대로, MIT |
| `bin/` | 실행기(`pi`), Node 탐색 | 자체 작성 |
| `compat/` | Node 20 호환 레이어 | 자체 작성 |
| `install.sh`, `update.sh`, `check-node.sh` | 설치·업데이트·진단 스크립트 | 자체 작성 |
| `profiles/jupyter/`, `profiles/common/` | `~/.pi/agent` 설정 템플릿·기본 지침, 공통 확장 | 자체 작성 |
| `tests/` | 단위 테스트 (설정 합치기, pi 확장) | 자체 작성 |

바이너리(실행파일, .node, .wasm, 이미지)는 들어 있지 않습니다. 제3자 소스의 출처와 해시는 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md) 에 있습니다.

## 0. 저장소 풀기
zip(`pi-agent-like-agent-api-main.zip`)을 code-server 탐색기로 홈에 올린 뒤 터미널에서 풉니다. 아래 안내는 `~/tools/pi` 기준입니다.
```bash
cd ~ && mkdir -p ~/tools && python -m zipfile -e ~/pi-agent-like-agent-api-main.zip ~/tools/ && mv ~/tools/pi-agent-like-agent-api-main ~/tools/pi
```
- 반드시 **홈 디렉터리(PVC) 아래**에 두세요. 그래야 파드를 재시작해도 남습니다.
- `unzip` 이 있으면 `unzip -q` 로 풀어도 됩니다. `python`·`unzip` 이 둘 다 없으면 GitHub 의 Tags 에서 `tar.gz` 를 받아 `tar -xzf <파일> -C ~/tools/` 로 풀고, 생긴 폴더 이름을 `~/tools/pi` 로 바꿉니다.
- `python -m zipfile` 은 파일의 실행 권한을 남기지 않지만, `bash install.sh` 로 실행하면 install.sh 가 권한을 줍니다.
- 이미 `~/tools/pi` 가 있으면 지우지 말고 [README 7장](../README.md#7-새-버전으로-바꾸기)의 `update.sh` 로 바꾸세요 (이전 판을 `~/tools/pi.old` 로 남기고 설정을 이어 줌).

## 1. Node.js 확인
```bash
bash ~/tools/pi/check-node.sh
```
`결과: 사용 가능` 또는 `호환 모드로 사용 가능` 이면 2단계로 넘어갑니다.

pi 실행기는 Node 를 다음 순서로 찾습니다. 22.19 이상을 먼저 고르고, 없으면 20.15 이상을 호환 모드로 씁니다.
1. `PI_NODE` 환경변수 (예: `export PI_NODE=/opt/node/bin/node`)
2. pip 패키지 `nodejs-wheel-binaries`, `playwright`(내장 Node)
3. PATH 의 `node`
4. code-server 내장 node (`/usr/lib/code-server/lib/node`)

code-server 의 판에 따라 들어 있는 Node 가 다릅니다 (Kubeflow 공식 노트북 이미지 기준).

| code-server | Node | pi |
|---|---|---|
| 4.89 이하 | 18 | 쓸 수 없음 (pip 의 Node 를 씀) |
| 4.93 | 20.15 | 호환 모드 |
| 4.121 이상 | 22.22 | 정식 |

Node 가 없거나 너무 낮으면 아래 중 하나를 준비합니다.

| 방법 | 명령 | 비고 |
|---|---|---|
| **Node.js 공식 바이너리 (PyPI)** | `pip install --user nodejs-wheel-binaries==24.16.0` | 권장. glibc 2.28 이상 |
| Playwright 내장 Node (PyPI) | `pip install --user playwright` | **1.46 이상**(Node 20.16+). `playwright install`(브라우저 다운로드)은 필요 없음 |
| 노트북에 있는 다른 node | `export PI_NODE=/경로/node` 를 `~/.bashrc` 에 | 20.15 이상. `check-node.sh` 가 Node 를 못 찾으면 흔한 곳에서 찾은 node 를 보여 줌 |

사내 pip 미러에 있는지 확인:
```bash
pip download --no-deps -d /tmp/pipchk nodejs-wheel-binaries==24.16.0
```

> **Kubeflow 에서는 반드시 `--user` 를 붙이세요.** `--user` 없이 설치하면 `/opt/conda`(컨테이너 이미지 영역)에 들어가 파드 재시작 시 사라집니다.
> `--user` 로 설치하면 홈(PVC)의 `~/.local` 에 남습니다.

**호환 모드(Node 20.x):** pi 는 공식적으로 Node 22.19 이상을 요구합니다. `compat/node20.mjs` 가 pi 가 쓰는 Node 22 전용 기능을 보충합니다.
- 보충하는 기능: `fs.globSync`, `Promise.withResolvers`, `process.getBuiltinModule`, `module.enableCompileCache`
- 기본 사용(read/write/edit/bash 도구, 대화, 세션)은 검증했지만 공식 지원 범위는 아닙니다.
- Node 22.19 이상을 쓸 수 있게 되면 자동으로 호환 레이어 없이 실행됩니다.
- 어떤 Node 로 실행되는지: `PI_DEBUG=1 pi --version`

## 2. 설치
```bash
bash ~/tools/pi/install.sh
# 새 터미널을 열고
pi --version
```
- `install.sh` 는 `profiles/jupyter/agent-template` 과 `profiles/common/agent-template` 을 `~/.pi/agent` 에 복사합니다 (이미 있는 설정 파일은 그대로 둠).
- PATH 를 `~/.bashrc` 에 넣고, 로그인 셸이 읽는 파일(`~/.bash_profile`·`~/.bash_login`·`~/.profile` 중 있는 것, 없으면 `~/.profile` 을 만듦)에도 한 줄 넣습니다.
  code-server·VS Code 터미널은 `~/.bashrc` 를, JupyterLab 터미널은 로그인 셸이라 `~/.profile` 쪽을 읽습니다. 설치한 그 터미널에서 바로 쓰려면 `export PATH="$HOME/tools/pi/bin:$PATH"`.
- pip 로 Node 를 설치한 경우, 그 Python 환경(conda env 등)이 터미널에서 활성화되어 있어야 찾을 수 있습니다.
  찾지 못하면 `python -c "import nodejs_wheel,os;print(os.path.dirname(nodejs_wheel.__file__))"` 로 경로를 확인한 뒤 `PI_NODE` 로 지정하세요.

### 새 버전으로 바꿀 때 (이미 설치한 경우)
[README 7장](../README.md#7-새-버전으로-바꾸기) 을 보세요. `bash ~/tools/pi/update.sh <받은 zip>` 이 폴더 바꾸기와 `install.sh` 실행까지 합니다.
- 기존 설정 파일(`settings.json`, `models.json`)에는 새 판에 추가된 항목만 넣고, 직접 고친 값(LLM 주소, 기본 모델 등)과 직접 지운 항목은 그대로 둡니다. 이전 파일은 `.bak` 으로 남습니다.
- 설정을 처음 상태로 되돌리고 싶을 때만 그 파일을 지우고 다시 설치하세요.

## 참고
- 실행기는 `PI_OFFLINE=1`(자동 네트워크 활동 끔)과 `PI_SKIP_VERSION_CHECK=1`(최신 버전 확인 끔)을 설정합니다. 설정 템플릿은 `enableInstallTelemetry: false` 입니다.
- code-server·VS Code 터미널(`TERM_PROGRAM=vscode`)에서는 실행기가 `--tui-mode fullscreen` 을 더합니다 (대화가 길 때 스크롤이 위로 감겼다 내려오는 것을 막음). 직접 `--tui-mode` 를 주거나 `/settings` 로 TUI mode 를 고르면 그 값을 씁니다.
- 기본 도구(read/bash/edit/write)는 추가 프로그램 없이 동작합니다.
- pi 시작 화면의 `Warning: fd not found ... / ripgrep not found ...` 는 무시해도 됩니다 (기본 도구는 이 둘 없이 동작하고, 입력창의 `@` 파일 목록은 키트의 확장 `files.ts` 가 fd 없이 보여 줌).
- 선택 사항인 `--tools grep,find` 를 쓰려면 ripgrep 이 필요합니다: `pip install --user ripgrep==14.1.0`
  (fd 는 pip 로 제공되지 않으므로 find 도구는 쓸 수 없습니다.)
- 이미지 축소(photon wasm)와 클립보드 붙여넣기 같은 네이티브 기능은 빠져 있습니다. 텍스트 기반 코딩 작업에는 영향이 없습니다.
