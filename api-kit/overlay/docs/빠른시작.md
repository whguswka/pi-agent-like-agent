# pi 빠른 시작 (한 장 요약)

Kubeflow 노트북(code-server·VS Code 웹)의 터미널에서 LLM API(vLLM 등)를 두뇌로 쓰는 코딩 에이전트입니다. 말로 시키면 파일을 읽고 고치고, 명령을 실행해 확인합니다.
자세한 설명은 [README](../README.md).

## 1. 설치 (처음 한 번)
1. 인터넷 PC 에서 GitHub 의 **Code > Download ZIP** 으로 받은 `pi-agent-like-agent-api-main.zip` 을 사내 반입 절차로 옮기고 ([수동 작업 절차](수동-작업-절차.md)),
   code-server 왼쪽 탐색기의 홈 폴더(`/home/jovyan`)에 끌어다 놓습니다.
2. 터미널(메뉴 ☰ > Terminal > New Terminal)에서. **이미 설치되어 있으면**(`~/tools/pi` 가 있으면) 이 세 줄 대신 이 장 끝의 '새 판으로 바꿀 때':
   ```bash
   cd ~ && mkdir -p ~/tools && python -m zipfile -e ~/pi-agent-like-agent-api-main.zip ~/tools/ && mv ~/tools/pi-agent-like-agent-api-main ~/tools/pi
   bash ~/tools/pi/check-node.sh        # 마지막 줄이 '결과: 사용 가능' 또는 '결과: 호환 모드로 사용 가능' 이면 됨
   bash ~/tools/pi/install.sh
   ```
- 새 판으로 바꿀 때 (pi 를 모두 끄고, 새 zip 을 홈에 올린 뒤):
  ```bash
  cd ~ && bash ~/tools/pi/update.sh ~/pi-agent-like-agent-api-main.zip
  ```
  자세한 것과 되돌리기: [수동 작업 절차 3·5장](수동-작업-절차.md#3-새-판으로-바꾸기)

## 2. LLM 연결 (처음 한 번)
1. `curl -s http://VLLM주소:8000/v1/models` 로 서버가 보이는지와 모델 이름(`"id"`)을 확인합니다.
2. `~/.pi/agent/models.json` 의 `baseUrl`(주소 + `/v1`), `models` 의 `id`·`contextWindow` 를 바꾸고, `settings.json` 의 `defaultModel` 도 같은 id 로.
3. **새 터미널**을 열고 `pi -p "bash 로 echo hello 를 실행하고 결과를 알려줘"` → hello 를 실행했다는 답이 나오면 됩니다.

자세히(키, 프록시, Ollama, 오류별 확인): [API 연결](API-연결.md). 시작 화면의 `Warning: fd not found ...`, `Warning: ripgrep not found ...` 두 줄은 무시합니다.

## 3. 매일 쓰기
```bash
cd ~/work/내프로젝트 && pi          # 시작 (pi -c: 이 폴더의 지난 대화 이어서)
```
할 일을 그대로 적고 `Enter`. 예: `@src/main.py 의 오류 처리를 고치고 테스트까지 돌려줘`
- 멈추기 `Esc` · 줄 바꾸기 `Shift+Enter` · 끝내기 `/quit` (`/exit` 도 됨)
- code-server 에서는 `Ctrl+P`(VS Code 빠른 열기), `Ctrl+J`(패널), `Ctrl+W`(브라우저 탭 닫기)를 pi 키로 쓰지 못합니다. `Shift+Enter` 가 바로 보내면 한 번 설정: [README 3-3](../README.md#3-3-code-server-터미널에서-다르게-쓰는-키)

## 4. 자주 쓰는 명령
| 명령 | 하는 일 |
|---|---|
| `/plan` | **계획부터**: 읽기만 하고 계획을 세움 → "이 계획대로 진행할까요?" 에서 고르면 진행 |
| `/mode ask` · `/mode auto` | 바꿀 때마다 확인하며 진행 · 묻지 않고 진행 (기본) |
| `@파일` | `@` 를 치고 파일을 고름. 보낼 때 파일 내용이 함께 가서 빠름 |
| `/undo` | pi 가 고친 파일을 요청 전으로 되돌림 (`/undo 2`: 두 요청) |
| `/remember <내용>` | 앞으로도 지킬 것을 지침(AGENTS.md)에 적음. 예: `/remember 커밋 메시지는 한국어로` |
| `/handoff` | 한 일·남은 일을 NOTES.md 에 정리 → 다음 날 `pi -c` 로 이어 가기 |
| `/review` · `/test` · `/commit` · `/explain 파일` | 변경 검토 · 테스트 돌리고 고치기 · 커밋 · 코드 설명 |
| `/skill:이름` | 스킬 쓰기 (노트북 요령 `kubeflow-notebook`, 데이터 분석 `data-analysis`, 보고서 `korean-report`, 디버깅 `debugging` 등) |
| `/wiki` | LLM 위키 (`/wiki init` 으로 만들고, 원본 반영 `/wiki ingest 파일`) |
| `/model` | 모델 고르기 (`Ctrl+L` 도 됨) |
| `/kit` · `/doctor` | 빠른 도움말 · 상태 요약 |

## 5. 작업 모드 세 가지 (상태 줄에 보임)
| 모드 | 언제 | 하는 일 |
|---|---|---|
| **계획** (`/plan`) | 큰 작업, 처음 보는 코드 | 파일은 읽기만. 계획을 보고 승인하면 진행하고, 진행 중 단계 목록이 체크됨 |
| **확인** (`/mode ask`) | 중요한 저장소 | 파일을 바꾸거나 명령을 실행하기 전에 바뀌는 줄(`-`/`+`)을 보여 주고 물음 |
| **자동** (`/mode auto`) | 평소 | 묻지 않고 진행. 폴더 지우기·`git push` 같은 위험한 명령만 물음 |

잘못 고쳤으면 `/undo`. 셸 명령으로 바뀐 파일은 되돌리지 못하니 중요한 폴더는 git 으로 관리하세요.

## 6. 막히면
- 사용법은 **`/kit`**. 문제가 생기면 **`/doctor`** 화면과 오류 메시지를 찍어 보내 주세요.
- LLM 서버 오류(`Connection error.`, `401`, `404` 등)와 명령을 실행하지 않는 경우: [API 연결 4·7장](API-연결.md#7-자주-나는-오류)
- 업데이트·되돌리기 같은 직접 하는 일: [수동 작업 절차](수동-작업-절차.md)
- 쓰지 말 것: `/share` (대화를 외부에 올림).
- pi 는 읽은 파일 내용과 명령 결과를 LLM 서버로 보냅니다. 개인정보·중요정보가 든 파일은 그 서버로 보내도 되는지 먼저 확인하세요.
